## 1. 打开速度怎么变快 — 首屏加载优化

### 首屏加载指标细化

1. **FP (First Paint 首次绘制)** : 页面开始渲染的时间点，通常是浏览器绘制第一个像素。
2. **FCP (First Contentful Paint 首次内容绘制)**: FP 到 FCP 中间其实主要是 SPA 应用 js 执行, 太慢就会白屏时间太长。
3. **FMP (First Meaningful Paint 首次有效绘制)**: 主要内容呈现的时间 (MutationObserver)。
4. **LCP (Largest Contentful Paint 最大内容渲染)**: 加载最大内容块呈现时间。
5. **INP (Interaction to Next Paint)** : 用户交互到下次绘制的时间，衡量用户交互后的响应速度。
6. **TTI (Time to Interactive 可交互时间)**: ssr
7. **TBT (Total Blocking Time 阻塞时间)**: 从 FCP 到 TTI：总的阻塞时间
8. **CLS (Cumulative Layout Shift 累计布局偏移)**: 累计布局偏移，重排、重绘
9. **TTFB (Time to First Byte 首字节时间)**: 服务器响应时间。

### 具体方案（结合项目背景）

1. 优化图片（webp、响应式图片）：使用懒加载技术，减少首屏资源请求。
2. 字体子集化：fontmin ttf 字体瘦身。
3. 懒加载：图片、视频、iframe、script、link
   - 图片懒加载：使用 `loading="lazy"` 属性。
   - 路由懒加载：Vue、React 等框架支持按需加载路由组件。
   - 组件懒加载：使用动态 import() 实现组件按需加载。
4. css、JavaScript 文件压缩,打包构建阶段完成(terser)

   - 代码压缩 terser、Gzip 压缩
   - 文件合并
   - 文件拆分
   - Tree shaking
   - 动态加载

5. 使用 SSR（服务端渲染）：提高首屏渲染速度，减少白屏时间。SSG （静态站点生成）：
   - Next.js、Nuxt.js 等框架支持。
   - 预渲染静态页面，减少首屏加载时间。

## 2. 动画卡顿

    为什么动画卡顿：单线程、ui渲染阻塞

### 优化手段

1. 减少主线程阻塞：将耗时操作放到 Web Worker 中执行，避免阻塞主线程。

   - 使用 `requestIdleCallback` 在空闲时间执行非关键任务。
   - 使用 `setTimeout` 或 `setImmediate` 将长任务拆分成小任务。
   - 使用 `requestAnimationFrame`：浏览器优化动画渲染，避免卡顿。
   - GPU 加速动画：使用 CSS `transform` 和 `opacity` 属性，利用 GPU 渲染，减少主线程压力。
   - 使用 `will-change` 优化动画：告诉浏览器动画将发生，提前计算动画帧。

2. 防抖节流：减少频繁触发的事件处理函数调用，避免过多重绘和重排。

   - **防抖**：在事件触发后延迟执行，只有最后一次触发才执行。
   - **节流**：限制事件处理函数的执行频率，定时执行。

## 3. 再次打开速度怎么变快 — 缓存优化

- **意义**：用户重复访问页面时，合理缓存能极大提升体验和降低服务器压力。
- **优化手段**：
  - **浏览器缓存策略**：合理使用 `Cache-Control`、`Expires` 头部控制强缓存和协商缓存。
  - **Service Worker 缓存**：PWA 技术让前端可离线缓存资源和数据。
  - **HTTP 缓存层级**：CDN 缓存 + 浏览器缓存 + 应用层缓存组合使用。
  - **数据缓存**：使用 IndexedDB、localStorage 存储数据，减少请求。
  - **缓存更新策略**：版本号更新（文件名带 hash）、差异更新机制。

## 4. 操作怎么才顺滑 — 渲染优化

- **意义**：用户操作（滚动、点击、动画）不卡顿，保证良好交互体验。
- **优化手段**：
  - **减少重排和重绘**：避免频繁操作 DOM，批量修改 DOM，使用 `transform` 和 `opacity` 动画代替布局相关属性动画。
  - **合并动画帧**：使用 `requestAnimationFrame` 统一动画调度。
  - **避免阻塞主线程**：长任务拆分、减少同步计算。
  - **虚拟列表**：长列表滚动时只渲染可视区内容。
  - **避免内存泄漏**：清理事件监听、定时器。

## 5. 动画怎么保证流畅 — 长任务拆分

- **意义**：复杂动画或任务阻塞会导致帧率下降，出现卡顿。
- **优化手段**：
  - **拆分长任务**：将耗时操作拆成多个小任务，通过 `setTimeout` 或 `requestIdleCallback` 分批执行。
  - **Web Worker**：将复杂计算放到子线程，避免阻塞主线程。
  - **使用 GPU 加速动画**：利用 CSS `transform`、`opacity`，减少主线程压力。
  - **避免布局抖动**：提前计算布局，减少强制同步布局。
  - **合理使用动画库**：选择性能好的动画库，如 GSAP。

## 6. 框架应用程：vue、react

### 状态管理

1. **减少全局状态的依赖**

   - 将状态尽可能局部化，避免使用全局状态（如 Redux 或 Context）管理所有数据。
   - **示例**：对于仅用于某些组件的状态，可以使用组件的 `useState` 或 `useReducer`。

2. **优化 Context 的性能**

   - Context 的更新会重新渲染所有订阅的组件。
   - **解决方案**：拆分 Context，将不同的逻辑存储在多个 Context 中，降低重新渲染范围。

3. **使用高效的状态管理库**

   - 使用轻量、高性能的状态管理工具，如 Zustand、Jotai 或 Recoil，它们具备更细粒度的状态更新机制。

4. **避免不必要的状态更新**
   - 使用 `useMemo` 和 `useCallback` 缓存计算结果和函数引用，避免不必要的重新渲染。

### 视图更新处理

1. Vue：使用 `v-once`、`v-memo` 优化组件渲染，减少不必要的重绘。
2. React：使用 `React.memo`、`useMemo`、`useCallback` 优化组件渲染，减少不必要的重绘。

# 总结

| 优化点       | 关键技术/手段                                 | 目标效果         |
| ------------ | --------------------------------------------- | ---------------- |
| 首屏加载优化 | 代码分割、SSR、资源预加载、图片优化           | 减少白屏时间     |
| 缓存优化     | HTTP 缓存、Service Worker、数据缓存           | 加快重复访问速度 |
| 渲染优化     | 减少重排重绘、虚拟列表、requestAnimationFrame | 操作流畅不卡顿   |
| 长任务拆分   | Web Worker、分批执行、GPU 动画                | 动画流畅不卡顿   |
