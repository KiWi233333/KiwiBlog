### 1. 用户登录的处理

- token (JWT、OAuth1-2.0 双 token)
- cookie（HttpOnly；SameSite: Strict、Secure）
- session（服务端存储，前端不直接操作）

### 2. axios 拦截 token

- 请求拦截：添加 token 到请求头
- 响应拦截：处理 token 过期或错误
  - 错误处理：刷新 token 或重定向到登录页

### 3. 7 天免登录的实现方法

| 方式                           | 描述                                   | 安全性 | 是否推荐            |
| ------------------------------ | -------------------------------------- | ------ | ------------------- |
| `localStorage`                 | 存储 JWT token + 过期时间              | 中     | ✅ 常用             |
| `cookie + token`               | 使用带 `HttpOnly` 的 Cookie 存 token   | 高     | ✅ 推荐（配合后端） |
| `refreshToken` + `accessToken` | accessToken 很短，refreshToken 存 7 天 | 高     | ✅ 最推荐           |

- 7 天免登录通常是通过 accessToken + refreshToken 机制来实现的。前端在登录时勾选“记住我”，后端返回长时间有效的 refreshToken，前端使用 accessToken 访问接口，在过期时用 refreshToken 自动续签，用户 7 天内无需重新登录。

- 在我的中是用的一种方式，出于开发成本采用单 token 的方式，前端存储在 `localStorage` 中，过期时间设置为 7 天。

### 4. 响应式设计方法

| 方法                              | 核心原理                                            | 优点                               | 缺点                               | 适用场景                           |
| --------------------------------- | --------------------------------------------------- | ---------------------------------- | ---------------------------------- | ---------------------------------- |
| 媒体查询（Media Query）           | 使用 `@media` 规则，根据视口宽度切换样式            | 简单、兼容性好、易于维护           | 需写多个断点、样式可能冗余         | 通用网页、组件库                   |
| 百分比/弹性布局                   | 使用 `width: %`、`em`、`rem`、`flex` 等相对单位布局 | 自动适应屏幕、代码简洁             | 可能需配合媒体查询补充边距字体调整 | 文本、图文混排、表单类布局         |
| vw / vh 单位                      | 使用 `vw` / `vh` / `vmin` / `vmax` 单位控制尺寸     | 可按屏幕宽度缩放，适合全屏设计     | 字体难控制、精度有限               | H5、Banner 页面、海报风格页面      |
| 栅格系统（Grid System）           | 利用预设列结构实现响应式布局（如 Bootstrap 的栅格） | 快速开发、多设备适配好             | 自定义布局难、样式结构受限         | 后台管理、CMS、官网模板            |
| 移动优先（Mobile First）          | 默认设计为移动端，逐步为更大屏幕添加样式            | 更适合现代移动用户、可减少加载内容 | 对老旧设备适配可能复杂             | 移动为主的产品，如 App 页、H5 页面 |
| 响应式图片（ `<picture>标签` ）   | 使用 `<picture>` / `srcset` 根据屏幕选择合适图片    | 提升加载速度、优化不同屏幕清晰度   | 编写较复杂、需准备多尺寸图片       | 资讯类站点、电商、相册             |
| CSS 容器查询（Container Queries） | 根据组件容器尺寸响应，而不是视口（新标准）          | 组件级响应式能力强，利于模块化开发 | 浏览器兼容性尚未普及               | 前端组件库、微前端、可嵌套组件     |

### 5. 怎么理解异步编程？js 为什么只有一个主线程？

    异步编程是为了解决 JS 单线程中耗时任务阻塞问题，JS 只有一个主线程，是因为要避免多线程修改 DOM 带来的复杂性和安全风险。通过事件循环机制，JS 能高效处理异步任务，实现流畅的用户体验。

- **异步编程**：允许代码在等待某些操作（如网络请求、文件读取）完成时继续执行其他任务，避免阻塞主线程。常用方式有回调函数、Promise、async/await。

- **JavaScript 单线程**：JavaScript 设计为单线程语言，主要是为了简化并发编程模型，避免多线程带来的复杂性和数据竞争问题。通过事件循环（Event Loop）机制，JavaScript 能够处理异步任务，将耗时操作放入任务队列，主线程继续执行其他代码。

  - JavaScript 最初是为浏览器设计的脚本语言，主要用于与 DOM 交互。
  - DOM 是非线程安全的，多个线程同时修改 DOM 可能引发冲突或状态混乱。
  - 为了避免复杂的线程同步问题（如加锁、死锁），JS 从一开始就设计为单线程执行。
  - 缺点：单线程执行，无法处理太多的复杂任务，所以开发者需要使用异步编程来处理耗时操作。

- **事件循环**：JavaScript 使用事件循环机制来处理异步任务。主线程执行完当前任务后，会检查任务队列是否有待处理的异步任务，如果有，就将其取出并执行。

### 6. 不同身份的用户怎么区分权限之类的？

    不同身份的用户授权功能，通常通过角色或权限列表控制用户能访问的路由、看到的菜单、可用的操作按钮等，前端通过动态路由、组件显示控制等手段实现权限隔离，后端通过 token 校验和权限表确保接口调用的安全性。

- **基于角色的访问控制（RBAC）**：根据用户角色分配权限，适用于权限管理较为简单的场景。
- **基于属性的访问控制（ABAC）**：根据用户属性、资源属性和环境条件动态决策，适用于权限管理复杂的场景。

- **权限控制方式**：
  - 路由（动态路由过滤）
  - 菜单（菜单级别权限）
  - 按钮（按钮级别权限）
  - 后端接口（接口级别权限）

### ✅ 1. `localStorage` / `sessionStorage` / `cookie`

| 特性           | localStorage         | sessionStorage             | cookie                       |
| -------------- | -------------------- | -------------------------- | ---------------------------- |
| 存储大小       | \~5MB                | \~5MB                      | \~4KB                        |
| 生命周期       | 永久（除非主动清除） | 页面关闭/刷新即清除        | 可设定过期时间               |
| 是否随请求发送 | ❌                   | ❌                         | ✅（自动随请求发送到服务器） |
| 使用场景       | 长期保存用户偏好等   | 页面临时状态（如表单缓存） | 登录状态、后端识别身份       |

### ✅ 2. `Promise` / `Promise.race` / `Promise.allSettled` / `Promise.all`

- `Promise`：用于处理异步操作，避免回调地狱。
- `Promise.all([...])`：**全部成功才成功**，有一个失败就失败。
- `Promise.race([...])`：**第一个完成（无论成功或失败）就返回**。
- `Promise.allSettled([...])`：**全部执行完后返回每个结果状态**（成功/失败都包含）。

📌 示例：

```javascript
Promise.all([p1, p2]); // 所有成功才进 then
Promise.race([p1, p2]); // 谁先完成就返回
Promise.allSettled([p1, p2]); // 都执行完，返回状态数组
```

### ✅ 3. 垂直水平居中（经典 CSS 问题）

常见 3 种方式：

#### 方法 1：Flex 布局（推荐）

```css
.parent {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

#### 方法 2：定位 + transform

```css
.child {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}
```

#### 方法 3：Grid 布局

```css
.parent {
  display: grid;
  place-items: center;
}
```

### ✅ 4. Less / Sass 简述

| 对比项   | Less                 | Sass                                     |
| -------- | -------------------- | ---------------------------------------- |
| 语法格式 | 类似 CSS             | 支持缩进（`.sass`）或 CSS-like (`.scss`) |
| 使用方式 | 浏览器 or 编译       | 编译（如 node-sass、dart-sass）          |
| 变量前缀 | `@color`             | `$color`                                 |
| 特点     | 更贴近 CSS，语法简洁 | 功能强大（继承、控制语句等）             |
| 主流使用 | Element UI、旧项目   | Vue3、React、SCSS 项目常用               |

📌 建议使用 `Sass（SCSS）`，生态更强。

### ✅ 5. 懒加载（Lazy Loading）

**定义**：按需加载资源，而不是页面初始全部加载，提高首屏速度。

#### 应用场景：

- 图片懒加载（提高首屏速度）
- 路由懒加载（优化单页体积）
- 组件懒加载（按需加载大组件）

#### 图片懒加载方式：

```html
<img
  loading="lazy"
  src="xxx.jpg" />
```

或通过 `IntersectionObserver` 判断图片是否进入视口。

### ✅ 6. 请求缓存（HTTP 缓存机制）

#### 两种方式：

1. **强缓存（浏览器直接用缓存）**

   - 通过 `Cache-Control: max-age` 或 `Expires`

2. **协商缓存（向服务器确认）**

   - `Last-Modified / If-Modified-Since`
   - `ETag / If-None-Match`

#### 前端控制缓存：

- axios 加随机参数 `?t=xxx` 禁用缓存
- 使用 Service Worker 进行缓存控制（PWA）

### ✅ 7. 页面渲染流程（浏览器渲染原理）

#### 浏览器渲染 6 步：

```txt
1. HTML 解析为 DOM Tree
2. CSS 解析为 CSSOM Tree
3. DOM + CSSOM 合并成 Render Tree
4. Layout（计算元素位置大小）
5. Paint（绘制图层）
6. Composite（合成图层、显示）
```

📌 一般页面白屏主要卡在：

- `HTML -> DOM`
- `资源加载（如 JS、CSS 阻塞）`
